# Audit 2026-10-22

Read-only audit of this repository at `528e5a3` (main). Nothing was changed; every finding is a proposal.

## Summary

- The content is consistent: every schema `$id`, its published copy under `docs/`, the index, the design version and the
  specification version agree.
- No secrets, personal data, local paths or internal references were found, in the working tree or in `git log -p --all`.
- Since the rule "every change goes through a pull request", every change on `main` arrived as a merged pull request (#1 to #5).
- Main gap: nothing checks these rules automatically. There is no CI and no `.gitignore`, and nothing verifies that `schema/`
  equals `docs/` or that the design copies match.
- Small drift: the specification names a version (0.22.0) that the README does not explain.

## What is in order

- All 12 `schema/*.schema.json` files are byte-identical to `docs/<name>/<version>.json` at their `$id`. Every JSON file
  under `docs/` has an `$id` that matches its path.
- `docs/index.html` lists every current schema, the earlier versions (0.14 to 0.17) and the design files. Every linked
  file exists.
- Design: `design/VERSION` (0.1.0) matches `tokens.json`, the header of `contextura.css` and the example pages.
  `docs/design/0.1.0/` is byte-identical to `design/`, and the tag `design-0.1.0` exists. Every token in `tokens.json` is
  present in `contextura.css`.
- `specification.md` (0.18, draft, 2026-10-21) matches the README. `AGENTS.md` has 32 lines, and `CLAUDE.md` is
  `@AGENTS.md`.
- Every JSON file in the repository parses. The READMEs have no dead links.
- Commits use the organization identity, not a personal name.

## Not checked

- The conformance cases were not validated against the schemas: no JSON Schema validator was available. Their expected
  results need the reference implementation, which is not in this repository.
- Branch protection and the Pages settings on GitHub were not checked, because the audit made no network calls.
